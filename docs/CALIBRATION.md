# Calibration data: design decisions

The calibration set of the SC 4.05 bpw quant has ~1.0M tokens in 180 rows, generated by the model itself. It is
published as three datasets: [agents](https://huggingface.co/datasets/Vemloir/Qwen3.8-Flash-Next-calib-agents),
[chat](https://huggingface.co/datasets/Vemloir/Qwen3.8-Flash-Next-calib-chat) and
[multimodal](https://huggingface.co/datasets/Vemloir/Qwen3.8-Flash-Next-calib-multimodal). This document explains why
it looks the way it does.

## Goal

Calibrate for how the model is actually used: coding agents (Codex, OpenCode, pi), chat in Russian and English, every
domain of the MiMo task pool, and every reasoning level. Russian was targeted at 10-20% of the tokens. The quant is
meant for other people too, so no area of use was left without data even where the author's own use is rare (images).

## Self-generated, not borrowed

Every assistant turn was written by the model (an EXL3 4.05 bpw quant), so the activations seen at calibration time
are the ones the model produces in use: its own reasoning style, tool-call format and turn structure. Prompts came
from elsewhere (below); responses never did.

Caveat: the generating model was a quant, not BF16. A quant's failure modes (for example repetition loops at high
reasoning effort) can leak into the trace; sessions that degenerated were dropped by hand (one session,
`full-045-cyber-pi-eff_off`, is excluded by name).

## Reasoning levels

The model's chat template supports `enable_thinking` off and `reasoning_effort` low / medium / xhigh. The first
calibration (v1) was generated at xhigh only; the model then looped more often at lower levels in use, which pointed
at the calibration missing those regimes. The current set mixes them by token budget:

| xhigh | medium | low | off |
|---|---|---|---|
| 40% | 20% | 15% | 25% |

The level is not visible in the conversation history a harness keeps (it lives in the chat template variables), so
the trace proxy (`agent-env/trace_proxy.py`) injects `enable_thinking` / `reasoning_effort` into each request from the
session name before forwarding and logging it, and the rows are rendered with the same template variables.

## Agent sessions (595k tokens, 59%)

- Tasks: [XiaomiMiMo/MiMo-V2.6-RL-oss](https://huggingface.co/datasets/XiaomiMiMo/MiMo-V2.6-RL-oss) (general agent,
  cyber, terminal-bench, code, webdev), selected by `agent-env/select_tasks.py`.
- Harnesses: Codex CLI, OpenCode and pi, each in Docker with memory limits, pointed at TabbyAPI through the logging
  proxy. Harness system prompts and tool definitions are part of the rows, since they are part of every real request.
- A row is a whole session (prompt, every tool call and result), up to ~135k tokens, so calibration sees long
  contexts with real tool traffic.
- Packing (`pack_v2.py`): sessions are taken round-robin over domains in random order so one domain cannot take the
  budget; outside xhigh each session is capped at 25k tokens; xhigh takes the longest sessions first (60% of its
  budget goes to agents).

## Chat (314k tokens, 31%)

- 65 conversations are the built-in prompts of exllamav3 `sc_trace.py` (science, math, code, writing, a few in
  Spanish and German), 39 are ours in Russian and English, 8 are music-notation requests (Chinese and English).
- Some are multi-turn: the model's answer is followed by a scripted follow-up and a second answer.
- 28 of 112 conversations are Russian; Russian conversations were packed first within each level's budget.

## Images (107k tokens, 11%)

Coding agents occasionally look at screenshots of the frontends they build, and users send charts and documents, so
the vision path needed calibration data even though it is a small share of use.

- 26 CoSyn figures (charts, tables, documents, circuits, chemistry, math, music, diagrams) with their dataset
  questions.
- 14 frontend screenshots: the model wrote a single-file page for a brief (MiMo webdev tasks and our own briefs,
  some asking for a deliberately broken layout), headless Chromium rendered it, and the model was asked to compare
  the page with the brief and list what is broken. Pages were kept compact (under 300 lines, 16k-token cap) because
  long pages were cut off mid-HTML and rendered blank; Chromium ran with a virtual-time budget so animations
  finished before the capture, and near-empty PNGs were dropped.
- 8 PixMo photos (published by URL only; the images are third-party).
- ~20% of the questions ask for the answer in Russian.

Images enter the model as vision-tower embeddings at fixed token positions. Stock exllamav3 conversion does not take
image rows, so the patched converter (`patches/exllamav3-1.6.1/0002-*`) runs the vision tower on each image and
substitutes the embeddings, the same way the generator does at inference (checked to be bit-identical).

## What is held out

Every source pool keeps a held-out part that calibration never saw (`trace_manifest.json`), used for the in-pool
evaluation traces. The headline evaluation does not use them: it uses two independent traces built from other
datasets (NVIDIA Nemotron post-training data, and a multilingual set), see EXPERIMENTS.md.
