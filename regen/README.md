# Calibration regeneration

The second calibration set is generated by NVIDIA's
[Qwen3.8-Flash-Next-FP4-Local](https://huggingface.co/nvidia/Qwen3.8-Flash-Next-FP4-Local) (quantization-aware
distillation from BF16, with explicit end-of-thinking and end-of-response losses) served by vLLM on a Colab G4
(RTX PRO 6000 Blackwell). The first set came from an EXL3 4.05 bpw quant and had cut-off reasoning (a 3072-token
per-turn cap), loops, broken multi-turn history and agent sessions built from 7 tasks; `qa.py` documents every check.

Only vLLM runs on the VM. Every client runs locally and reaches the server through an SSH port forward
(`127.0.0.1:18000`); agent harnesses keep running in local Docker containers behind `agent-env/trace_proxy.py`.

## Run order

```sh
regen/g4.sh up                 # allocate G4, start g4_serve.sh (model ~10 min, container ~10 min)
regen/g4.sh wait               # until vLLM answers
regen/g4.sh forward &          # 127.0.0.1:18000 -> VM:8000, holds the VM's single SSH slot
export REGEN_API_KEY=$(cat ~/.config/sc-quant/regen_api_key)

python regen/gen_chat.py   -o regen/out/chat.jsonl              # 243 conversations x 4 modes
python regen/gen_images.py -o regen/out/images.jsonl            # 105 images, one mode each

python agent-env/trace_proxy.py --upstream http://127.0.0.1:18000 --vllm --api_key_env REGEN_API_KEY \
    --log_dir regen/out/agent-logs &
python agent-env/run_agents.py --tasks regen/agent_tasks.json --runs regen/out/agent-runs \
    --cap_tokens 200000 --max_minutes 90 --parallel 3

regen/g4.sh down
python regen/qa.py --chat regen/out/chat.jsonl --images regen/out/images.jsonl -o regen/out/qa.json
```

Every generator is resumable (records are appended per finished job; a rerun skips them and retries errors).

## Files

| File | Role |
|---|---|
| `g4.sh`, `g4_serve.sh` | VM lifecycle, model and container download, vLLM launch (model card's RTX PRO 6000 settings) |
| `common.py` | streaming client, reasoning modes, runaway-loop stop, resumable store |
| `gen_chat.py` | chats: sc_trace seeds, own RU/EN conversations, `prompts_ru.json`, music prompts |
| `gen_images.py` | CoSyn, PixMo and frontend screenshots, no tools, language set by the request |
| `select_agent_tasks.py`, `agent_tasks.json` | 40 fresh MiMo tasks, one per session, one mode each |
| `qa.py` | reject / review verdicts per record |
| `mock_vllm.py` | stand-in server for testing the clients |

No generation length cap is set anywhere: a response ends on its own, at the 262k context limit, or when a
runaway loop is detected (the same 200-character block 20 times in a well-compressing tail; such records are kept
for inspection and never become rows).
