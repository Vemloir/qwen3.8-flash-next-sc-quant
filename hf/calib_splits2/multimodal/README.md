# Qwen3.8-Flash-Next self-generated calibration data: images

Part of the calibration data of the self-calibrated EXL3 quant of
[Qwen/Qwen3.8-Flash-Next](https://huggingface.co/Qwen/Qwen3.8-Flash-Next) ([Vemloir/Qwen3.8-Flash-Next-sc-exl3](https://huggingface.co/Vemloir/Qwen3.8-Flash-Next-sc-exl3)). The full set has three parts: [agents](https://huggingface.co/datasets/Vemloir/Qwen3.8-Flash-Next-calib-agents), [chat](https://huggingface.co/datasets/Vemloir/Qwen3.8-Flash-Next-calib-chat), [multimodal](https://huggingface.co/datasets/Vemloir/Qwen3.8-Flash-Next-calib-multimodal),
2,151,377 tokens together. These are the rows that went into calibration; all generated rows (5.0M tokens, a
superset of these) are in [Vemloir/Qwen3.8-Flash-Next-traces](https://huggingface.co/datasets/Vemloir/Qwen3.8-Flash-Next-traces).

One image and one question per row, with the model's answer. The image enters the model through the
vision tower: `image_token_start` and `image_token_count` give the span of image placeholder tokens in the row,
which a converter replaces with the vision embeddings. The screenshot rows ask the model to compare the page it built
with the brief and list what is missing or broken.

| Source: CoSyn / frontend screenshots / PixMo | 60 / 29 / 16 |  |

Fields: `reasoning`, `lang`, `source`, `category`, `question`, `qa`, `image` (path in `images/`) or `image_url` and `image_sha256`, `image_token_start`, `image_token_count`, `turns`.

## Files

- `data.jsonl`: one line per row. `id`, `tokens`, the metadata fields above, `text` (the row decoded with the
  Qwen3.8 chat template's special tokens) and `input_ids`.
- `cal_trace.safetensors`: the same rows in exllamav3 `convert.py --cal_data` format (`input_ids` right-padded to
  the longest row, `lengths`), plus the images of the image rows (`mm_row`, `mm_start`, `mm_len`, `mm_image_<k>`: raw
  bytes); feeding them to the vision tower at conversion time needs a converter that supports image rows (the
  PixMo rows are text-only in this file).
- `images/`: the CoSyn figures and the frontend screenshots.

Every row was generated by Qwen3.8-Flash-Next itself, served as NVIDIA's
[FP4-Local](https://huggingface.co/nvidia/Qwen3.8-Flash-Next-FP4-Local) checkpoint in vLLM, with no output length cap, at one
of four reasoning levels (`xhigh`, `medium`, `low`, `off`, set through the chat template), and checked for
truncated reasoning, loops and language slips (`regen/qa.py` in the
[code repository](https://github.com/Vemloir/qwen3.8-flash-next-sc-quant)); rejected records are not included.

## Uses

Suitable for:

- **Calibrating quantized models** of Qwen3.8-Flash-Next or close relatives (EXL3, GGUF importance matrices, AWQ/GPTQ
  and similar): the text is the model's own distribution, with agent sessions, reasoning at four levels, many
  languages and images. `cal_trace.safetensors` is ready for exllamav3 `convert.py --cal_data`.
- **SFT / distillation** of smaller models, as one component of a larger mix: whole agent sessions with real
  coding-agent harnesses and tool results, multi-turn chats, science in 16 languages, image questions.
- **Evaluating quantized models or inference engines** on the model's own outputs (teacher-forced KL divergence
  against BF16, as done for the quant above).

Limitations:

- Generated by NVIDIA's FP4-Local checkpoint, not by the BF16 model, and like any distillation
  data it carries the teacher's mistakes.
- Quality checks cover truncation, loops and language slips only: answers were not checked for correctness, and agent
  sessions are not labelled with task success.
- Small as a primary SFT set (2.15M tokens across all parts); English and Russian dominate the
  chat, the other 14 languages have a few rows each.
- Agent sessions contain files and tool output from the task repositories (their own licenses) and container paths.
  The data was scanned for credentials and personal data before publishing.
- Published works made with it, including trained models, need attribution under ODbL; the model outputs are also
  subject to the Qwen Community License as far as it reaches.

## Versions

This is calibration set 2 (2026-10-18), used by the current version of the quant. Set 1 (~1M tokens, used by the
first version) is the earlier revision `05ed49b98732db2588be953807492415555d5ff8` of this repository, kept only so that the first version can
be reproduced: it has reasoning cut off at a 3,072-token limit, a few looping answers and agent sessions truncated
at 25k tokens, and is not meant for any other use.
