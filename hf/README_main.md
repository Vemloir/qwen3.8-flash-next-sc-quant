# Qwen3.8-Flash-Next EXL3, self-calibrated

EXL3 quants of [Qwen/Qwen3.8-Flash-Next](https://huggingface.co/Qwen/Qwen3.8-Flash-Next), converted from BF16 with
calibration data generated by the model itself: coding-agent sessions, chats in Russian, English and 14 more
languages at four reasoning levels, images. With the same model size in memory as turboderp's 4.05 bpw quant,
**15-17% lower KL divergence from BF16** on two independent traces that played no part in calibration. Code,
calibration data and evaluation data are all public, so the quant can be reproduced end to end.

| Branch | Bits per weight | Head | Vision | Model files | n-gram table | Requires |
|---|---|---|---|---|---|---|
| [4.05bpw_sc_h8_ng8](https://huggingface.co/Vemloir/Qwen3.8-Flash-Next-sc-exl3/tree/4.05bpw_sc_h8_ng8) | 4.05 (4.0498) | 8 bpw | 8 bpw | 69 GB | 52 GB, 8 bpw | exllamav3 >= 1.6.1 |

```
hf download Vemloir/Qwen3.8-Flash-Next-sc-exl3 --revision 4.05bpw_sc_h8_ng8 --local-dir Qwen3.8-Flash-Next-sc-exl3-4.05bpw
```

## Results

KL divergence of the output distribution against BF16, measured with exllamav3 qbench, teacher-forced on assistant
turns; lower is closer to the full model. The reference is turboderp's
[4.05bpw_h6_ng6](https://huggingface.co/turboderp/Qwen3.8-Flash-Next-exl3/tree/4.05bpw_h6_ng6): the same size in
memory (68.6 GB of model files here, 68.4 GB there). The n-gram table, which is streamed from disk and not loaded into
memory, is 8-bit here (52 GB) and 6-bit there (39 GB), so this quant takes 13 GB more on disk.
Positions the chat template writes itself (`<think>\n`, or `<think>\n\n</think>\n\n` with reasoning off: 166 of
23k scored tokens on the Nemotron trace, 32 of 26k on the multilingual one) are left out for all quants: the model
never generates them in real use, while a teacher-forced trace scores them as part of the answer.

![Mean KL divergence from BF16, this quant against turboderp's 4.05 bpw, on two traces](assets/kld_overall.png)

| Trace | Rows | Scored tokens | This quant | turboderp 4.05 | Difference, 95% interval | Rows lower |
|---|---|---|---|---|---|---|
| NVIDIA Nemotron 3.5 Super post-training conversations | 48 | 23k | **0.00767** | 0.00903 | **-15.1%** [-22.4%, -7.3%] | 39 / 48 |
| Multilingual (Russian + 9 languages) | 52 | 26k | **0.00543** | 0.00656 | **-17.2%** [-25.5%, -9.5%] | 42 / 52 |

Intervals come from a paired bootstrap over rows. Perplexity (as qbench reports it, over all scored tokens) is
unchanged within noise: 1.9275 against 1.9316 on the
Nemotron trace (BF16 1.9285), 2.3385 against 2.3443 on the multilingual one (BF16 2.3420).

![Distribution of per-token KL divergence for both quants on both traces](assets/kld_hist.png)

The same comparison token by token: the bulk of the distribution is shifted slightly left and the tail of large
errors (right of 1e-2) is thinner. Medians: 8.5e-4 against 1.10e-3 (Nemotron), 9.9e-4 against 1.17e-3
(multilingual). Unlike turboderp's histograms, there is no noise-floor curve: it needs a separate BF16 run with
injected noise.

Caveats: the head is 8 bpw here against 6 in turboderp's quant (+~150 MB, outside the bits-per-weight budget in
both), and the n-gram table 8-bit against 6-bit; part of the gain comes from them. Calibration data, bit allocation,
expert Hessians, head, n-gram table and exllamav3 version all differ from the reference at once, so the gain is not
attributed to any one of them. turboderp's quant was converted with exllamav3 1.4.4; later versions added post-LDLQ
refit, LDLQ drift compensation and other converter improvements, so part of the gain comes from the newer converter.
The affinity-weighted Hessians alone gave 3.6% in an isolated test (see below). Two sources are slightly worse than the reference, multi-turn instruction following
(+3.4%) and Italian (+6.0%, one of four rows); both intervals cross zero. Outside Russian there are only 4 rows per language; the per-language numbers are
indicative.

### Against turboderp's SC quants

turboderp has since published self-calibrated quants of his own. His
[SC 4.18 bpw](https://huggingface.co/turboderp/Qwen3.8-Flash-Next-exl3/tree/4.18bpw_h6_ng8) (revision `9796a106`),
on the same traces against the same BF16 reference, template-written positions left out:

| Trace | This quant (120.4 GB) | turboderp SC 4.18 (121.8 GB) | Difference, 95% interval | Rows lower |
|---|---|---|---|---|
| NVIDIA Nemotron 3.5 Super post-training conversations | **0.00767** | 0.00841 | **-8.9%** [-17.0%, -0.5%] | 28 / 48 |
| Multilingual (Russian + 9 languages) | **0.00543** | 0.00609 | **-10.8%** [-17.8%, -3.3%] | 33 / 52 |

Both carry an 8-bit n-gram table of the same size (51.8 GB; the tables themselves differ), so the size difference is
in the model weights: 68.6 GB here (4.05 bpw, 8-bit head) against 70.0 GB (4.18 bpw, 6-bit head). His SC 4.18 is 7%
below his plain 4.05 on both traces, with both intervals crossing zero. Counting the template-written positions, as
plain qbench does, the Nemotron difference is -7.4% [-15.6%, +1.3%]. SC 4.18 was scored on an RTX PRO 6000 (Colab
G4) and this quant on an RTX 5070 Ti, with the same exllamav3 tree and the same cached reference logits.

## Versions

| Date | Calibration | Nemotron | Multilingual | Revision |
|---|---|---|---|---|
| 2026-10-18 (current) | set 2: 2.15M tokens, regenerated without a length cap and quality-checked | 0.00767 | 0.00543 | `4.05bpw_sc_h8_ng8` |
| 2026-10-16 | set 1: ~1M tokens | 0.00788 | 0.00545 | `524a19ebbbd653cd8cf31b766a56e7183133d7a0` |

The second version changes only the calibration data: same recipe, flags and exllamav3 patches. Set 1 had reasoning
cut off at a 3,072-token limit, a few looping answers and agent sessions truncated at 25k tokens; set 2 has none of
these. The difference between the two versions is within noise: -2.6% [-10.1%, +5.7%] on the Nemotron trace, -0.3%
[-4.6%, +4.6%] on the multilingual one. (The first version of this card scored the template-written positions too
and gave -12.4% and -16.9% against turboderp for set 1.) The previous version stays available with
`--revision 524a19ebbbd653cd8cf31b766a56e7183133d7a0`.

## What is different

- **Self-generated calibration** (2.15M tokens): 17 agent sessions in Docker (Codex, OpenCode and pi harnesses on
  MiMo tasks, whole sessions; the longest is 201k tokens), 222 chats (science in 16 languages, everyday Russian and English,
  music), 105 image prompts (charts, documents, frontend screenshots, photos) run through the vision tower; 25%
  Russian; reasoning levels mixed as xhigh 40%, medium 20%, low 16%, off 24%. Generated with NVIDIA's
  [FP4-Local](https://huggingface.co/nvidia/Qwen3.8-Flash-Next-FP4-Local) checkpoint of the model in vLLM, with no
  output length cap, then checked for truncation, loops and language slips.
- **Measured bit split in the experts**: in layers 0-9 the routed experts' down projection gets more bits than
  gate/up (3/3/5 in layer 0, 3.5/3.5/5 in 1-7 and 9), elsewhere 4/4/4; chosen from the expert output error of every
  2-6 bit combination per layer.
- **Affinity-weighted expert Hessians**: each of the 512 experts per layer is quantized against its own Hessian,
  tokens weighted by the expert's router probability, instead of one Hessian shared by all of them. In an isolated ablation (Gemma 4 26B A4B, 3.0 bpw, everything else identical) this alone lowered KL divergence
  from BF16 by 3.6% [-6.2%, -0.8%], for ~40% longer conversion; details in
  [EXPERIMENTS.md](https://github.com/Vemloir/qwen3.8-flash-next-sc-quant/blob/main/docs/EXPERIMENTS.md).
- **Dense tensors**: shared experts, attention k/v and the sparse-attention indexer at 8 bpw, GDN out_proj at 7,
  other dense layers at 6; output head and vision tower at 8.

## Running

Tested with TabbyAPI on exllamav3 1.6.2.

| Setup | Value |
|---|---|
| GPU / CPU | RTX 5070 Ti 16 GB, Ryzen 9 9950X |
| Context | 262,144 tokens |
| Expert layers on CPU | 45 of 48 (`--cpu-moe-offload-layers 45`; with 44 the cache does not fit) |
| VRAM in use | ~14.0 GB |
| System RAM in use | ~56 GB |
| Generation | ~33 tokens/s |
| n-gram table | streamed from disk by default (`ngram_ram: false`), does not need to fit in RAM |

With exllamav3 >= 1.6, do not set `EXL3_GR_MIX_TILED=0`: it keeps extra copies of the hyper-connection tables in
VRAM and the model no longer fits.
